================================================================================
1. WHAT IS THIS WEBSITE?
================================================================================

This is a single-page, cinematic, fully animated marketing/showcase website
dedicated to the Dodge Challenger SRT Demon — one of the most powerful and
controversial factory-built muscle cars ever produced. The site functions as
an immersive digital experience, not a transactional site.

The experience is designed to feel like a film or a high-end car brand editorial
rather than a standard web page. Every section uses scroll-triggered animations,
parallax effects, particle systems, canvas drawings, and motion libraries to
create a dramatic and immersive atmosphere.

The website has 10 main content sections (plus a footer):
  - Hero
  - Frame Sequence  ← NEW (scroll-driven cinematic 480-frame animation)
  - Specs
  - Performance
  - Gallery
  - Engineering
  - Timeline
  - Configurator
  - About
  - Footer (with a cinematic call-to-action)

2. PROJECT PURPOSE & DISCLAIMER
================================================================================

The footer explicitly states: "An independent cinematic tribute to the Dodge
Challenger SRT Demon. Not affiliated with Stellantis."

This means the site is a fan/tribute project — a creative portfolio-level
demonstration, NOT an official Dodge or Stellantis product page. It is
connected to Lovable (lovable.dev), an AI-assisted web app builder, meaning
the project was originally scaffolded and iterated with AI tools.

The AGENTS.md file instructs developers (and AI agents) to never rebase, amend,
or force-push commits to the connected branch, because Lovable syncs git history
and rewrites there would break the Lovable project editor.

7.01 — PRELOADER  (src/components/demon/Preloader.tsx)
────────────────────────────────────────────────────────────────────────────────

PURPOSE:
  Covers the entire viewport while the site "boots up." Mimics the feeling of
  an engine starting and systems initializing before the race begins.

VISUAL ELEMENTS:
  1. Background: Solid --jet black, full-screen, with film-grain texture overlay.

  2. Rising red ambient glow at the bottom: a radial gradient that grows in
     opacity as the progress value increases from 0 to 100. At 0% progress it's
     barely visible; at 100% it's fully bright and red — like embers rising.

  3. Two headlights: Two circular elements positioned in the center of the
     screen, spread apart like a car's headlights approaching. They start dim
     (8% opacity) and grow in size/brightness with progress. At the final flash
     moment they scale up to 3.4x and bloom fully white.

  4. "SRT DEMON" title: Animated in with letterSpacing going from 0.6em to
     0.12em (letters appear to slam together). "DEMON" uses the ember-text
     gradient (red-to-orange). Initial opacity: 0, animates to 1.

  5. RPM bar visualizer: A row of 40 vertical bars. Each bar is:
     - Progressively taller (left to right, 25% to 100% height)
     - Lit (white) or unlit (dark) based on whether the bar index crosses
       the current progress percentage
     - The last 8 bars (the "red zone", i > 31) glow in --glow-red
     - Each lit bar has a subtle random scaleY jitter to simulate meter bounce

  6. Status text line: Shows the current loading stage name on the left and
     the zero-padded percentage ("047%") on the right, in monospace uppercase.

  7. Progress bar: A thin horizontal line at the bottom. Red fill grows from
     left to right matching progress. Has a red box-shadow glow.

LOADING STAGES (shown based on progress bracket):
  0–20%:  "INITIALIZING IGNITION"
  21–41%: "PRIMING FUEL SYSTEM"
  42–62%: "SPOOLING SUPERCHARGER"
  63–83%: "CALIBRATING TRANSBRAKE"
  84–100%: "DEMON AWAKE"

PROGRESS SIMULATION:
  A setInterval fires every 90ms. Each tick adds a random value (1.5 to 7.5)
  to the current progress, creating an uneven, engine-like ramp. When it
  reaches 100, the interval clears.

COMPLETION SEQUENCE:
  1. At 100%: wait 250ms, then trigger setFlash(true)
  2. Flash: all headlight elements instantly scale/brighten. A white full-screen
     overlay flashes in and out (opacity 0 → 0.85 → 0 over 550ms) — simulating
     a high-beam blast or a camera flash.
  3. At 1250ms after 100%: setGone(true) and call onDone() callback.
  4. onDone() sets ready=true in the Index component, which activates Lenis.
  5. AnimatePresence exit: the preloader scales up slightly and blurs out.

7.02 — CURSOR  (src/components/demon/Cursor.tsx)
────────────────────────────────────────────────────────────────────────────────

PURPOSE:
  Replaces the default OS cursor on desktop (non-touch) devices with a custom
  magnetic, glowing cursor system that reacts to interactive elements.

COMPONENTS:
  1. Red dot: A small 6x6px red circle (--demon color) with red glow box-shadow.
     This snaps directly to the actual mouse position every frame.

  2. Ring: A larger circle with a red border (--primary/70). This LAGS behind
     the cursor position using linear interpolation (lerp factor 0.16 per frame),
     creating a spring-like trailing effect. The ring is 34x34px normally.

ACTIVE STATE (when hovering an element with data-cursor attribute):
  - The ring expands to 76x76px
  - Gets a semi-transparent demon-colored background (16% opacity)
  - Gets backdrop-filter: blur(2px) — frosted glass effect
  - A label can appear inside the ring (see data-cursor labels below)

DATA-CURSOR LABELS used across the site:
  data-cursor="true"      → Just enlarges ring, no text label
  data-cursor="go"        → Shows "GO" inside ring (hero CTA button)
  data-cursor="top"       → Shows "TOP" (Nav logo, scrolls to hero)
  data-cursor="sound"     → Shows "SOUND" (audio toggle when off)
  data-cursor="mute"      → Shows "MUTE" (audio toggle when on)
  data-cursor="drag"      → Shows "DRAG" (gallery slide area)
  data-cursor="prev"      → Shows "PREV" (gallery prev button)
  data-cursor="next"      → Shows "NEXT" (gallery next button)
  data-cursor="zoom"      → Shows "ZOOM" (gallery fullscreen button)
  data-cursor="explode"   → Shows "EXPLODE" (engineering engine view)
  data-cursor="assemble"  → Shows "ASSEMBLE" (engineering engine, after explode)

VISIBILITY: The cursor component is only rendered on md+ screens (hidden on
mobile), and only becomes visible after the first pointermove event fires.
On touch/coarse-pointer devices, the entire effect is skipped via matchMedia.

7.03 — ATMOSPHERE  (src/components/demon/Atmosphere.tsx)
────────────────────────────────────────────────────────────────────────────────

PURPOSE:
  A fixed, full-viewport canvas positioned behind all content (z-5), rendering
  atmospheric particle effects and volumetric fog. Adds cinematic depth and
  movement throughout the entire scrolling experience.

PARTICLE SYSTEM — three types:
  1. dust    (55% spawn rate): tiny floating particles (0.4–1.5px radius),
                                very slow vertical drift, low opacity (0.28),
                                white/grey color. Simulates lens dust.

  2. ember   (33% spawn rate): medium particles (0.7–2.5px), moderate upward
                                drift, orange-red color with a large 7x radius
                                glow halo. Simulates rising sparks/embers.

  3. spark   (12% spawn rate): fast-moving streaks, rendered as lines (not
                                dots), orange color, high velocity, short trails.
                                Simulates welding sparks or hot metal debris.

PARTICLE BEHAVIOR:
  - Each particle spawns at the bottom (y = height + random offset above).
  - They rise upward with vy velocity (-0.15 to -2.3 px/frame depending on type).
  - They drift horizontally with vx velocity and a sine-wave perturbation.
  - Life counter: each particle has a maxLife (260–780 frames). When exceeded,
    or when y < -60, the particle is replaced with a new spawn.
  - Fade curve: alpha follows a sine fade-in/fade-out (sin(life/maxLife * π)).

VOLUMETRIC FOG:
  Three large radial gradients positioned across the screen, moving slowly in
  circular paths using sine/cosine waves. The center fog bank has a slight red
  tint (rgba(209,18,23,0.055)), while the others are grey-blue. Each has a
  radius of 35–43% of the viewport. These are redrawn every frame with different
  positions (shift by sin/cos of time).

CURSOR LIGHT BLOOM:
  A 320px radial gradient follows the pointer position (tracked via pointermove).
  Color: rgba(255,59,59,0.05) → transparent. Adds a subtle red spotlight effect
  wherever the cursor is hovering. This is drawn on top of the fog, before the
  particles, giving a layered depth.

MOVING LIGHT SHAFTS (non-canvas):
  Two div elements with tall (180% height) vertical gradients, rotated 12°,
  animated horizontally using the @keyframes sweep. One is white/70, the other
  is primary red/80. They move across the background with 18s and 26s loop times,
  staggered by 4s, creating the feeling of searchlights or cinematic lens flares.

VIGNETTE + GRAIN:
  A full-screen film-grain overlay (using the .film-grain utility) and an inset
  box-shadow vignette (28vw spread, rgba(0,0,0,0.85)) darken the edges, keeping
  focus on the center.

PERFORMANCE CONSIDERATIONS:
  - prefers-reduced-motion: If the user has this preference set, the particle
    count drops to 30 instead of the normal ~170, and animations are gentler.
  - devicePixelRatio is clamped to max 2 to avoid massive canvas buffers on
    high-DPI displays.
  - Canvas is set to "lighter" composite mode when drawing particles, making
    overlapping particles add brightness (physically plausible glow behavior).

CANVAS DIMENSIONS:
  - Resizes on window resize events
  - Width/height match viewport exactly (innerWidth, innerHeight)
  - DPR scaling ensures crisp rendering on retina screens

7.04 — NAV  (src/components/demon/Nav.tsx)
────────────────────────────────────────────────────────────────────────────────

PURPOSE:
  Fixed top navigation bar. Provides site-wide navigation between all 8+
  sections, shows active section highlighting, and hosts the engine audio toggle.

NAVIGATION LINKS (8 items):
  { id: "hero",         label: "Home" }
  { id: "specs",        label: "Experience" }
  { id: "performance",  label: "Performance" }
  { id: "gallery",      label: "Gallery" }
  { id: "engineering",  label: "Technology" }
  { id: "timeline",     label: "Timeline" }
  { id: "configurator", label: "Configurator" }
  { id: "about",        label: "About" }

ACTIVE SECTION TRACKING:
  An IntersectionObserver watches all 8 section elements simultaneously with
  rootMargin: "-45% 0px -50% 0px" — this means a section is only "active" when
  the middle 5% of the viewport aligns with it. As the user scrolls, the active
  label updates. The active link gets a red underline (--primary color bar) that
  slides between links using Framer Motion's layoutId="nav-underline" — a shared
  layout animation.

SCROLL BEHAVIOR:
  - Clicking any nav link calls scrollIntoView({ behavior: "smooth", block: "start" })
  - On mobile, the menu closes automatically on navigation

SCROLLED STATE:
  When window.scrollY > 40px, the nav gains:
  - Border bottom: 1px solid rgba(255,255,255,0.05)
  - Background: rgba(--jet, 0.70) with backdrop-blur-xl (18px blur)
  - Reduced vertical padding (py-3 instead of py-6)
  At the very top of the page, the background is transparent.

LOGO:
  "SRT" in white display font, "DEMON" in --primary (red) with glow-text class.
  Clicking it scrolls to hero. Has data-cursor="top" for custom cursor label.

MOBILE MENU:
  Below lg breakpoint (1024px), a hamburger/X icon button appears.
  Clicking it opens a slide-down overlay with all navigation links in large
  display font, with a glass-panel background (backdrop blur).

ENGINE AUDIO TOGGLE (useEngineAudio hook, internal to Nav.tsx):
  A button with Volume2 (on) or VolumeX (off) icon.
  When turned ON, it synthesizes an idling V8 engine sound using the
  Web Audio API — no external audio files are loaded.

  HOW THE V8 ENGINE AUDIO IS SYNTHESIZED:
    Three oscillators are created:
      - 42 Hz sawtooth: deep low-end rumble (gain 0.5)
      - 63 Hz sawtooth: sub-harmonic body resonance (gain 0.14)
      - 126 Hz square:  upper harmonic (gain 0.14)
    All three are filtered through a lowpass BiquadFilter (220 Hz cutoff, Q=6)
    to remove harshness and simulate the air-box/exhaust resonance.

    LFO modulation on each oscillator:
      - Three LFOs (7.5 Hz, 8.5 Hz, 9.5 Hz) modulate each oscillator's frequency
        by 3–9 Hz, creating the lopey, uneven idle rhythm of a big-block V8.

    Noise bed for exhaust texture:
      - A 2-second buffer of white noise (Math.random) is created once and looped.

      - Initially 0. On enable: setTargetAtTime(0.09, ..., 0.8s) — smooth fade-in.
      - On disable: setTargetAtTime(0, ..., 0.3s) — smooth fade-out.

  The audio only initializes once. Toggling off just fades the gain to 0;
  the oscillators keep running silently to avoid audio context teardown cost.

7.06 — FRAME SEQUENCE  (src/components/demon/FrameSequence.tsx)  ← NEW
────────────────────────────────────────────────────────────────────────────────

PURPOSE:
  A scroll-driven, fully pinned cinematic frame sequence section that plays 480
  pre-rendered JPG frames as a continuous animation controlled entirely by the
  user's scroll position — like Apple's iPhone product pages or Porsche's
  configurator scroll reveals. No video, no autoplay. Every frame advance is
  100% under the user's scroll control.

POSITION IN PAGE: Directly between <Hero /> and <Specs />.

SECTION ID: "frame-sequence"

FRAME DATA:
  Total frames:  480
  Sequence 1:    public/car1/ezgif-frame-001.jpg → ezgif-frame-240.jpg (240 frames)
  Sequence 2:    public/car2/ezgif-frame-001.jpg → ezgif-frame-240.jpg (240 frames)
  File format:   JPG (served from /public, accessible as /car1/... and /car2/...)
  Naming:        Zero-padded 3 digits (001–240)

SCROLL MECHANICS — THE STICKY CONTAINER TRICK:
  The outer <section> has height = calc(100vh + 2880px).
  The sticky inner div has height = 100vh, position = sticky, top = 0.
  This means:
    - When the top of the section reaches the viewport top, the inner canvas
      "sticks" and stays fixed.
    - The user scrolls 2880px while the canvas appears frozen in place.
    - During those 2880px, scroll position is mapped to frame index.
    - When the section bottom exits the viewport, the sticky releases and
      normal page scrolling resumes into the Specs section.
  No JS-based scroll locking. No pointer-event blocking. Lenis is unaffected.

SCROLL → FRAME MAPPING:
  scrolled = -(section.getBoundingClientRect().top)
  progress = clamp(scrolled / 2880, 0, 1)
  frameIndex = Math.round(progress × 479)

  PX_PER_FRAME = 6 (6 pixels of scroll per frame).
  SCROLL_HEIGHT = 480 × 6 = 2880px total pinned travel.
  At 6px/frame the pacing closely matches Apple product page scroll feel.

  Scrolling forward: frameIndex increases (animation advances).
  Scrolling backward: frameIndex decreases (animation reverses perfectly).
  No autoplay. Zero playback without scroll input.

LENIS INTEGRATION:
  Primary: subscribes to lenisInstance.on("scroll", handler) — the highest-
  fidelity hook into Lenis's smooth scroll tick, fired every RAF frame.
  Fallback: window.addEventListener("scroll", handler) — covers the period
  before Lenis initialises (it is dynamically imported).
  lenisInstance is exported from hooks.ts as a module-level ref that is set
  once Lenis initialises and nulled on destroy.
  The component does NOT create any additional scroll system.

PRELOADING — ALL 480 FRAMES:
  On mount, 480 HTMLImageElement objects are created immediately.
  Each gets img.decoding = "async" (browser hint for off-thread decode).
  All 480 .src values are set at once, triggering parallel network requests.
  A counter increments on each load/error event (errors count as settled to
  prevent hangs on a single bad frame).
  setLoadStatus("ready") is called only when all 480 have settled.
  Until ready, a full-screen preload overlay is shown (z-115) with a red
  progress bar and percentage counter matching the site's Preloader aesthetic.
  On unmount, all img.src values are cleared to abort pending requests.

CANVAS RENDERING:
  A single <canvas> element covers the sticky viewport.
  DPR-aware: canvas.width = window.innerWidth × min(devicePixelRatio, 2).
  On window resize, canvas dimensions update and lastDrawnRef resets to -1
  to force an immediate redraw.
  Draw algorithm — "cover" fit:
    scale = max(canvas.width / img.naturalWidth, canvas.height / img.naturalHeight)
    Centred: dx = (canvas.width - img.naturalWidth × scale) / 2
    ctx.clearRect then ctx.drawImage — single call, no intermediate buffers.
  GPU compositing: canvas has willChange:"transform" for compositor promotion.
  ctx.imageSmoothingEnabled defaults to true (bilinear, crisp on all DPRs).

RAF RENDER LOOP:
  requestAnimationFrame loop runs continuously once ready.
  Each tick: if frameRef.current !== lastDrawnRef.current → drawFrame().
  Otherwise: no draw call (zero wasted GPU work when scroll is idle).
  The loop uses refs exclusively — no React state in the hot path means zero
  re-renders during playback.

ENTER TRANSITION (from Hero):
  Hero's bottom gradient fades to var(--jet).
  FrameSequence has a top gradient overlay: var(--jet) → transparent (h-40).
  Result: Hero exits into black, frame sequence fades up from black. No hard cut.
  Canvas opacity transitions from 0 → 1 over 0.9s once images are ready.

EXIT TRANSITION (into Specs):
  FrameSequence has a bottom gradient overlay: var(--jet) → transparent (h-48).
  Specs section sits on var(--jet) background (like all sections).
  Result: last frame gently dissolves into the Specs background. Seamless.

VISUAL OVERLAYS (in render order, all pointer-events:none):
  1. Canvas                    — fullscreen, GPU-composited frame playback
  2. Vignette (inset shadow)   — 28vw inset, rgba(0,0,0,0.82), darkens edges
  3. Top fade gradient         — var(--jet) → transparent, h-40
  4. Bottom fade gradient      — var(--jet) → transparent, h-48
  5. Scanlines (.scanlines)    — 18% opacity, matches site-wide CRT texture
  6. Ember glow (bottom)       — radial gradient, --demon 18%, adds atmosphere
  7. ScrollHint                — "Scroll to reveal" indicator, auto-hides

SCROLL HINT:
  A pulsing vertical red gradient line + "Scroll to reveal" eyebrow text.
  Appears with a 0.5s delay after the section becomes visible.
  Hides on first scroll event or after 3 seconds (whichever comes first).
  AnimatePresence handles the fade-out.

STATE (React):
  loadStatus: "loading" | "ready"   — controls overlay visibility and canvas opacity
  loadProgress: 0–100               — drives preload progress bar

REFS (no re-renders):
  imagesRef   — HTMLImageElement[] array of all 480 loaded images
  frameRef    — current target frame index (written by scroll handler)
  lastDrawnRef— last frame actually drawn (compared in RAF to skip redundant draws)
  rafRef      — requestAnimationFrame ID for cleanup
  canvasRef   — the canvas DOM element
  sectionRef  — the outer section element (for getBoundingClientRect)

HOOKS.TS CHANGE (supporting this component):
  lenisInstance is now exported from hooks.ts as a typed module-level variable.
  It is set to the Lenis instance after dynamic import resolves.
  It is nulled when Lenis is destroyed.
  Type: { raf, destroy, on, off } — the minimum surface needed.
  This allows FrameSequence to subscribe directly to Lenis scroll events
  without drilling props or using context, keeping the component self-contained.

9. CUSTOM HOOKS  (src/components/demon/hooks.ts)
================================================================================

THREE HOOKS + ONE EXPORTED REF:

── lenisInstance (module-level export) ──
  Type: { raf, destroy, on, off } | null
  Set to the live Lenis instance after its dynamic import resolves.
  Nulled back to null when Lenis is destroyed (on component unmount).
  Exported so that FrameSequence can subscribe to Lenis scroll events
  directly via lenisInstance.on("scroll", handler) without prop-drilling,
  context, or creating a second scroll system.
  This is the minimum Lenis API surface needed — just raf, destroy, on, off.

── useSmoothScroll(enabled: boolean) ──
  Dynamically imports Lenis (code-split, loaded async).
  Creates a Lenis instance with: duration:1.25, smoothWheel:true, lerp:0.09
  (lerp = linear interpolation factor; 0.09 = slow, silky smooth).
  Runs Lenis.raf() in a requestAnimationFrame loop.
  Only initializes when enabled=true (i.e., after preloader finishes).
  Sets lenisInstance to the created instance on init.
  Nulls lenisInstance on cleanup.
  Cleanup: cancels RAF, calls lenis.destroy() on unmount.

── useCountUp(target, decimals, duration) ──
  Returns: { ref (for a <span>), display (string) }
  An IntersectionObserver watches the ref element.
  When it first enters the viewport (threshold 0.4 = 40% visible):
    - Starts a RAF animation loop for `duration` ms (default 1800ms)
    - Uses cubic ease-out: 1 - (1-t)^3
    - Counts from 0 to target, formats with .toFixed(decimals)
  Once started, never re-triggers (started.current ref flag).

── useHydrated() ──
  Returns: boolean
  Starts as false. Sets to true in a useEffect (runs only on client).
  Used in Index to guard browser-only components (Cursor, Atmosphere, Preloader)
  from running during SSR, preventing hydration mismatches.

10. GLOBAL CSS & ANIMATIONS  (src/styles.css)
================================================================================

KEYFRAME ANIMATIONS:

  grain (0.6s, steps(2)):
    Translates an ::after noise element in random small offsets (0% → -3%/2% →
    2%/-3% → -2%/-2% → 0%). Creates rapid film grain texture movement.

  breathe (9s, ease-in-out, infinite):
    scale(1) translateY(0) ↔ scale(1.012) translateY(-6px)
    Applied to hero car image: subtle living, breathing zoom effect.

  idle-shake (0.16s, linear, infinite):
    Sub-pixel translations: (0,0) → (0.6px,-0.4px) → (-0.5px,0.5px) → (0.4px,0.6px)
    Simulates engine vibration. Applied to hero car image wrapper.

  pulse-glow (2.4s, ease-in-out, infinite):
    opacity 0.35 ↔ 1. Applied to glowing indicator dots (ping rings, hotspots).

  sweep (single pass, used with custom durations):
    translateX(-120%) skewX(-18deg) → translateX(320%) skewX(-18deg)
    The diagonal white/red sheen across background light shafts and button hover.

  rise (used in particle-related contexts):
    translateY(0) scale(1) → translateY(-260px) scale(0.4), with opacity fade.
    General upward floating animation.

Tailwind v4 @utility declarations register .display, .eyebrow, .glass-panel,
.ember-text, .glow-text, .scanlines, .breathe, .idle-shake, .pulse-glow
as first-class utility classes usable directly in JSX className strings.

12. PERFORMANCE & ACCESSIBILITY CONSIDERATIONS
================================================================================

PERFORMANCE:
  - All section images use loading="lazy" (except the hero, which is eager).
  - Images have explicit width and height attributes to prevent layout shift (CLS).
  - The hero image is high-priority and uses scale-110 (extra pixels pre-loaded
    for parallax movement without layout gaps).
  - Lenis smooth scroll is delayed until after preloader, reducing initial JS work.
  - Lenis is dynamically imported (import("lenis")) — code-split, not in main bundle.
  - devicePixelRatio is capped at 2 on the canvas elements to limit memory use.
  - prefers-reduced-motion is respected in Atmosphere (drops particle count to 30).
  - The custom cursor is disabled on touch/coarse-pointer devices (matchMedia check).
  - All animations use transform and opacity (GPU-composited properties) rather
    than layout-triggering properties like width/height/top/left wherever possible.

ACCESSIBILITY:
  - All images have descriptive alt text.
  - Atmosphere canvas has aria-hidden="true" (decorative, not content).
  - Cursor overlay has aria-hidden="true".
  - Navigation buttons have descriptive aria-label where icon-only.
  - Gallery prev/next/expand buttons have aria-labels.
  - Engine hotspot buttons have aria-label set to the system name.
  - Audio toggle button has aria-label="Toggle engine audio".
  - Keyboard navigation supported in gallery (ArrowLeft/ArrowRight/Escape).
  - Interactive spec cards support both hover and focus events for keyboard users.
  - Color selection swatches have aria-label with color name.
  - Text contrast follows the dark-on-dark design (white text on near-black bg,
    red accents on dark backgrounds — high contrast ratios).

SCROLL BEHAVIOR:
  html { scroll-behavior: auto } — native smooth scroll is disabled.
  Lenis takes over all scroll handling for consistent cross-browser behavior.
  Lenis uses lerp:0.09 (slow, cinematic) and duration:1.25.

14. SUMMARY OF USER EXPERIENCE FLOW
================================================================================

When a user opens the website, here is the exact sequence of events:

  1. PAGE LOAD
     The page loads with a pure black background. Lenis smooth scroll is NOT
     active yet. The browser renders the shell but keeps the Preloader on top.

  2. PRELOADER (3–5 seconds)
     A fake progress counter ramps up erratically, simulating a V8 engine
     startup sequence. RPM bars animate. Stage labels cycle through ignition
     phases. Two headlights grow brighter. At 100%, a white flash fires.
     The preloader scales up and blurs out.

  3. HERO SECTION REVEALED
     The car image appears with idle-shake + breathe animations running.
     "SRT" and "Demon" words slam up from behind a mask. The subheadline and
     CTA button fade in with staggered delays. Lenis smooth scroll is now active.

  4. FRAME SEQUENCE — Cinematic Scroll-Driven Animation  ← NEW
     Immediately after the Hero section the page enters a pinned 2880px scroll
     zone. The viewport appears frozen while the user scrolls:
     - 240 frames of car1 play frame-by-frame as the user scrolls down.
     - Without any flash or reset, 240 frames of car2 continue immediately after.
     - Scrolling backward reverses the animation perfectly.
     - All 480 frames were preloaded into memory before this section became
       visible, so playback is always instant with zero network lag.
     - When the 480th frame is reached, the section unpins and scrolling
       continues normally into the Specs section.

  5. SCROLLING THROUGH SECTIONS
     Every section uses scroll-triggered animations (whileInView from Framer
     Motion). Headers wipe in. Images reveal with clip-path. Stats count up.
     The canvas Atmosphere renders continuously in the background.
     The Nav tracks which section is visible and updates its active indicator.

  6. SPECS — Interactive
     Hover spec cards to move the glowing hotspot around the car diagram.
     The detail card cross-fades with blur transition.

  7. PERFORMANCE — Animated Canvas
     The speedometer needle sweeps to 203 MPH with overshoot. RPM counts up.
     Six metrics count up from zero as they enter the viewport.

  8. GALLERY — Cinematic Slideshow
     Drag, swipe, or press arrow keys. Ken Burns zoom on each photo.
     Click expand for fullscreen lightbox.

  9. ENGINEERING — Interactive Diagram
     Hover or click system names to highlight engine hotspots.
     Click the engine to enter exploded view.

  10. TIMELINE — Historical Journey
      Hover years on the progress line to travel from 1969 to 2023.
      The red progress line springs to the selected year.

  11. CONFIGURATOR — Build Your Demon
      Change paint, wheels, calipers, environment, spoiler, lighting.
      Watch the car image update with CSS filters and color overlays.
      Price updates in real time.

  12. ABOUT — Heritage & Statistics
      Stats count up on scroll. Tunnel image wipes in.

  13. FOOTER — Cinematic Outro
      Parallax driving image. "Power Beyond Limits" headline slams in.
      CTA to return to top. Navigation links. Social icons.

  PERSISTENT ELEMENTS (throughout entire scroll):
    - Custom cursor (desktop): glowing dot + lagging ring, changes on hover
    - Atmosphere canvas: floating embers, sparks, fog, light shafts
    - Engine audio (optional): synthesized V8 idle via Web Audio API
    - Nav bar: transparent at top, frosted glass after 40px scroll
